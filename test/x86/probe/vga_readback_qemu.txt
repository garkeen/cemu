# Dual run of test/x86/probe/vga_readback.asm, 2026-10-16, same 512-byte boot
# sector on both models:
#
#   cemu  --machine x86 --isa x86 vga_readback.bin
#   qemu-system-i386 -drive file=vga_readback.bin,format=raw,if=ide,index=0 -boot c \
#       -display none -serial file:... -no-reboot \
#       -device isa-debug-exit,iobase=0xf4,iosize=0x4
#
# The suite cell is a ref cell: cemu's live transcript must equal the `qemu` line.
# Exit: debug-exit value 9 -> status 19 on both.
cemu vga-rb 00012A2003FF4BF5676FF70380F910a00b00f06gY
qemu vga-rb 00012A2003FF4BF5676FF70380F910a00b00f06gY

**Both models agree on every field.** Case `6` (`in 0x3BA` while the
miscellaneous output register reads 0x67) used to differ because this card
answered `00` from a misreading of the IBM VGA TR: the text claimed IOCS16
selected only the CRTC pair, but the register references (FreeVGA/VGAREGS) put
the whole 0x3Bx/0x3Dx base under that bit and place Input Status 1 at 3BA/3DA
accordingly, which is also what QEMU's `vga_ioport_invalid` gates. The
divergence is withdrawn: with misc bit 0 set, 0x3B0-0x3BF is not decoded and
floats high; 0x3C0-0x3CF (attribute controller, sequencer, DAC) always decodes,
which is why the gate never dropped the firmware's 3C0/3C4/3C6 writes.

Every other field agrees, including the two cases that used to be wrong:

  - case `9` reads 0x3CA (feature control) and both answer `10` — written 0x11,
    and bit 0 is not part of what the latch returns. It used to read 0x3DA here,
    which is *input status 1*: an answer that depends on where the raster is at
    that instant, so the case was measuring the clock rather than the latch.
  - case `g` is the retrace property, printed as a judgement (Y = both phases
    seen, N = one missing) rather than a count. Both models answer `Y`. The probe
    reads 0x3DA until both phases have appeared (bounded at ~1.3M reads): the
    correct vertical pulse is CR10..CR11's few lines (3 lines on this table,
    ~0.7% of a frame), so a fixed 200-sample count can miss it and report N on a
    card that pulses correctly. The count itself is not in the transcript: it
    depends on where in the frame the guest happens to poll.
