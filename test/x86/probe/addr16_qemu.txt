# Dual run of test/x86/probe/addr16.asm, 2026-10-21, same 512-byte boot sector
# on both models:
#
#   cemu --machine x86 --isa x86 addr16.bin
#   qemu-system-i386 -drive file=addr16.bin,format=raw,if=ide,index=0 -boot c \
#       -display none -serial stdio -no-reboot \
#       -device isa-debug-exit,iobase=0xf4,iosize=0x4
#
# Transcript: five bytes at SS:0928, a space, two bytes at SS:0947.
# 464F4E0000 = F O N and two untouched bytes; 4445 = D E.
# Exit: debug-exit value 5 -> status 11 on both.
cemu addr16 464F4E0000 4445
qemu addr16 464F4E0000 4445

The five raw-encoded stores exercise both halves of SDM vol.1 table 2-1's
16-bit addressing:
  88 82 64 FF  [bp+si-0x9c] with BP=09C4, SI=0/1: the 16-bit sum 10928 wraps
               to 0928/0929 before the SS base is added, and SI must take part.
  88 83 64 FF  [bp+di-0x9c] with DI=2: rm=3 must add DI.
  88 42 80     [bp+si-0x80] disp8 with SI=3 -> 0947.
  88 43 80     [bp+di-0x80] disp8 with DI=4 -> 0948.
A model that drops SI/DI from rm 2/3 or keeps the 32-bit sum writes all five
stores 64K away and prints zeros. The Windows 1.01 display driver's font-name
parser uses exactly the first encoding; with the wrong answer its buffer stays
empty and KERNEL never matches the loaded FONTS module.
